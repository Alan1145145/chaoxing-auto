# 模型能力与浏览器修复

完整目标保持不变；用户要求全程自主修复、不再提问。下拉选择框与页面向下滚动均有问题。

## 必须完成并验证

1. 模型接入旁提供可保存的思考模式及联网搜索按钮；按接口实际能力发送参数，不能只改界面。覆盖现有 OpenAI 兼容、千问、DeepSeek、Anthropic、Gemini，并保留旧配置、密钥和内置豆包。
2. 内置浏览器应像正常浏览器：新标签打开链接并保留原页，标签切换/关闭，主页、前进后退、刷新/停止和常用快捷键；同一浏览器共享登录，不同浏览器隔离；课程脚本/自动化绑定正确标签。
3. 修复模型与默认模型下拉选择、搜索、键盘/鼠标选择及长列表滚动；修复课程页向下滚动与布局高度。
4. 修复 OCS JS 悬浮窗松手、失焦、移出窗口、取消拖动和下拉交互后的黏鼠标；不能使整个页面或菜单选项变成拖动区域。
5. 修复 OCS JS 加载后的卡顿：减少同步设置 IPC/XHR、重复解密/磁盘写入、无变化轮询写入，保留配置同步、iframe 和跨标签状态。
6. 用真实 Electron/WebView 和离线模型 HTTP fixtures 做行为回归；比较关键的输入/拖动/滚动表现与存储调用量。不能只凭类型检查宣告完成。
7. 构建可直接试用的新版，保留回退版本，更新启动入口和修复记录。只有上述要求全部经当前证据验证，才能完成 goal。

## 已确认的源代码证据

- E1：`app/src/window.ts` 的 popup handler 对 `target=_blank` 和 window.open 一律执行当前 guest.loadURL，原页被覆盖。
- E2：`embedded-storage.ts` 每次 get/has/set 都读文件、解密；set 即刻加密写盘。运行器 GM_setValue 同步阻塞 IPC，iframe 使用同步 XHR。
- E3：easy-us 的老鼠标拖动仅监听 document mouseup/mousemove，不检查 buttons、失焦或取消；菜单内控件事件也会向上触发拖动。
- E4：当前模型请求没有思考/联网参数，保存和读取配置也没有对应字段。
- E5：模型及导航页面尚待真实运行复现下拉与滚动问题；不得仅凭 CSS 猜测完成。
